## Why this change

Three Qwen-only experiments did not reliably resolve the actual geographic-scope
failure. The model could describe the source as customers *outside China* yet
approve a claim including customers *in China*. Even selecting the correct literal
source sentence did not fix its decision. Those failed experiments remain in
`eval/results`; the relation-level [review](relation_review_20261025.md) records
the initial 14/16 result and token-limit failure.

- `scope_audit_20261025T173803_438085Z.json`: comparing two model-derived scope
  descriptions worked on the real pair, but these descriptions were not proven
  source text.
- `scope_audit_20261025T173914_900526Z.json`: original evidence still produced a
  false approval and a false rejection of a faithful Turkish summary. The run
  stopped after 12/16 cases; the remaining four were not completed.
- `passage_checks_20261025T174234_156106Z_587b33db.json`: the correct original
  design-out sentence was selected, but the wrong scope was still approved.
  The experiment stopped on its first mismatch as configured.

## Independent model experiment

The publisher's multilingual
[mDeBERTa NLI model](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli)
classifies premise/claim pairs as entailment, neutral or contradiction. We use
the publisher's quantized ONNX file on CPU, with two intra-operation threads.
The pinned files total 355,011,595 bytes; no PyTorch or Transformers installation
was needed. The repository revision and SHA-256 hashes are in
[`configs/nli_model.json`](../../configs/nli_model.json).

The fixed development threshold was 0.8 before scoring. These classifier scores
are **not calibrated probabilities of factual correctness**.

NLI correctly rejected the real wrong geographic scope and accepted its faithful

## Runtime boundary

1. The existing citation binding limits a claim to its cited sources.
2. Source sentences and their preceding context retain exact offsets. Their
   combined premise is sliced directly from the source, including original
   separators; it is not regenerated by the model.
3. NLI selects the highest-scoring passage per source above the fixed threshold.
   Its classification input includes the filing ticker from source metadata so
   that "our" can be attributed to the issuer. This attribution is not inserted
   into the literal witness and cannot be quoted as source text.
4. Qwen receives these actual passages and must still support the entire claim
   with exact quotations. NLI acceptance alone never releases a response.
5. Required source coverage is preserved. Extra citations must be removed or a
   compound narrative split; unrelated source text cannot be added as support.
6. Missing/corrupted model files, non-finite output, or context overflow fail
   closed. Inputs are not silently truncated. NLI decisions, selected source
   offsets, scores, threshold and model identity are recorded in the trace.

The pinned model is loaded lazily and reused within a process. Its files are
verified on load. No download occurs during an answer. The configured directory
is `financial_data/models/mdeberta_nli`, excluded from Git. Provision it with:

```sh
.venv/bin/python -m src.verification.nli --download
```

`llm.claim_nli` enables the guard for callers using the project settings. Custom
callers supplying their own LLM configuration must include this field to enable
it. Only narrative claim checks use NLI; source-free and financial-only paths
retain their existing verification. The Qwen generation model remains 8B.

## Limits and validation

The model has a 512-token pair limit. Sentence splitting is a heuristic; fragments
and anaphora may still require more context. Requiring a single supporting
passage per cited source can reject legitimate synthesis across multiple passages.
The appropriate repair is to split the claims, not to bypass the check. Neither
classifier nor LLM has been shown reliable on all filing claims or languages.

280 focused tests passed after integration. They cover model-file integrity,
literal offsets, score shape/finiteness, overflow rejection, no silent bypass,
source identity/metadata, source coverage, LLM rejection after NLI approval, and
the existing agent/data/RAG boundaries. Installed dependencies passed `pip check`.
The setup command was also rerun successfully without redownloading valid files.

The first integrated 20-case suite produced 18/20 expected decisions, rejecting
two supported Turkish claims. It exposed missing issuer attribution in the NLI
input and sentence splitting inside `U.S. Department`/`U.S. Entity List`.
The model threshold was not lowered. Source-metadata attribution and protected
dotted initials address those input problems. The original failed run remains:
[`claim_regressions_20261025T175453_953621Z_dea52a1e.json`](../results/claim_regressions_20261025T175453_953621Z_dea52a1e.json).

The repeated integrated suite completed with **20/20 expected decisions and no
errors**, in 179.69 seconds. It includes the real scope pair, six relation-transfer
controls, eight earlier synthetic controls, and four source-citation swaps:
[`claim_regressions_20261025T175844_110810Z_c031026d.json`](../results/claim_regressions_20261025T175844_110810Z_c031026d.json).
This is a development regression result, not an independent general benchmark.
Fresh MCP execution is evaluated separately; 20/20 is not an end-to-end result.
